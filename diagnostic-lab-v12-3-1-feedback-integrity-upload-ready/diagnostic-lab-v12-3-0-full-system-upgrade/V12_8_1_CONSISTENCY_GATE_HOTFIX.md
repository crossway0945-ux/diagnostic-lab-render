# V12.8.1 — Enforced Final Cross-Section Consistency Gate (hotfix on V12.8.0)

Layered on the verified V12.8.0 build (check-source 79 modules, 27 test files green). This hotfix adds
the **enforced final consistency gate** that V12.8.0 was missing — a validator that runs over the
*fully assembled student view model* and repairs cross-section contradictions before the report is
saved or rendered. **Honest scope: 2 of the reported defect categories are fixed and verified against
the real Sun saved report; the rest are listed as pending. No fabricated "all green" claim.**

## Reproduced from the REAL saved report (Sun, Problem & Solution, band 6.0–6.5, 2026-07-26)

The attached production JSON (progress export → newest P&S record) was loaded through the actual
deterministic pipeline. Two contradictions were reproduced in the saved `studentReportViewModel`:

- **§5 status ↔ explanation:** `frameworkBreakdown["Thesis Route Clarity"] = { status:"Strong",
  diagnosis:"The thesis does not yet establish the required route clearly." }` — Strong paired with a
  "does not establish route" explanation.
- **§13 Paragraph Coverage ↔ dimensions:** Body 1 & 2 status strings said "Development **Controlled**"
  while their `dimensions.development` was "**repair-needed**".

## Root causes (pinned to code)

1. `validateStatusExplanationCompatibility` (domain/reportConsistency.js) missed adverb-inserted
   negations: it flagged "does not establish" but **not** "does not **yet** establish" (verified:
   `pass:true` with "yet", `pass:false` without).
2. There was **no enforced gate** over the assembled view model — the audit ran on canonical
   `frameworkScores`, but the rendered `frameworkBreakdown`/`paragraphCoverage` could still ship a
   contradiction. This is exactly the "no combined final-output validator" gap.

## Fix (domain/reportConsistency.js + domain/reportViewModels.js)

- Broadened the validator regex to tolerate up to two adverbs between the negation and the verb.
- Added `enforceViewModelConsistency(viewModel)` — the enforced final gate (brief §4/§5/§13):
  - **Framework:** a positive status (Strong/Aligned/Controlled) whose explanation contradicts it gets
    a status-compatible, non-fabricating explanation. The **frozen status is preserved** — scoring is
    never rerun (§8).
  - **Paragraph Coverage:** the multi-dimension status string is rebuilt from the *conservative union*
    of the status string and the `dimensions` object, so a "Development Controlled" label can never
    hide a "development: repair-needed" dimension. "Strong"/"Functionally Strong" (Intro/Conclusion)
    are left untouched.
- Wired the gate into `buildStudentReportViewModel` — the single assembly chokepoint used by both
  `aiAnalyzer` and `apiRouter` — so every report passes through it before assert/save/render.
